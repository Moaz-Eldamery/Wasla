# Clinical database (wasla_clinical)

Prisma schema and migrations for `wasla_clinical`: the `auth` and `core` schemas.

**Rule:** Must always match `schema.md`. Update both in the same change.

## Files

- `schema.prisma`: every table and enum in the `auth` and `core` schemas. The rules Prisma can't express are listed in `schema.md` under "Raw SQL in the first migration".
- `prisma.config.ts`: Prisma CLI settings: schema, migrations folder, and the database to migrate (`MIGRATOR_DATABASE_URL`, as `wasla_migrator`).
- `seed.mts`: fake demo data (KAN-13): departments, clinics, staff with the demo logins, patients, free slots, and past visits simulated with realistic waits. Runs as `wasla_migrator` on Node 24 directly (`docker compose run --rm seed` or `pnpm db:seed`), only into an empty database, in one transaction. Same data every run, apart from IDs and dates.
- `migrations/`: one folder per migration, generated by Prisma. The first one (`…_init`) also holds the hand-written SQL listed in `schema.md`. Applied by the `migrate` service or `pnpm db:migrate`.
